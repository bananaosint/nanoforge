# Mixture of Experts models

Select **Mixture of Experts (MoE)** in the Studio's **Architecture** selector. This creates a new Custom model; it does not convert existing dense checkpoint weights. Choose experts per layer (2–64), experts per token (1–expert count), layers, heads, width/context and router loss coefficients, then **New experiment**. The budget fitter and hard <1B parameter limit count **all** expert/router weights. The preview also shows an active-path parameter estimate, including embedding tables. It is not a peak-memory or FLOP estimate.

Each transformer layer replaces its dense GELU MLP with independent expert MLPs and a learned linear router. Routing logits, softmax, load balancing and router z-loss use FP32 under mixed precision. Each token is sent to its top-k experts with weighted outputs accumulated back into the residual stream. For k>1 the selected weights normalize to one; top-1 retains its full softmax probability so the language loss can train the gate (Switch-style). Routing is dropless: there is no capacity truncation or token dropping.

Default coefficients are 0.01 for the load-balancing objective and 0.001 for router z-loss. They are averaged across layers. Pretraining/SFT add them to training cross-entropy; validation reports language-model cross-entropy without these auxiliary terms. DPO adds the policy's chosen/rejected auxiliary losses while retaining a fixed reference and disabled dropout. DataParallel applies replica-local router losses and combines sums/counts without gathering full vocabulary logits. SFT padding positions participate in router balancing; the language targets remain masked normally.

CPU and CUDA paths support training, generation, attention inspection, checkpoint save/load/upload/download and optimizer resume for MoE. All experts/router tensors and settings travel in the `.pt`. **MoE checkpoints require the updated Studio**; old dense checkpoints still load, and dense exports retain their previous model-config/state-key format. Model exports remain CPU FP32, regardless of training precision. Each GPU holds all experts; this implementation does not shard experts across devices. Unselected expert optimizer states are created lazily by AdamW when those experts first receive gradients.

This is a sparse reference implementation using per-expert indexed dispatch. It does not evaluate every expert on every token, but it is not a fused/grouped-GEMM expert kernel. Dynamic dispatch and small expert batches can limit GPU utilization, so a MoE does not promise faster training than a comparable dense model. Parameter memory includes every expert; DPO also needs a frozen reference. Profile actual throughput and memory before scaling. The TPU/XLA CLI explicitly rejects MoE because its static-shape requirements are not handled by this dispatch implementation.

CPU tests check routing against manually evaluated experts, top-1/2/all-expert gradients, exact parameter counts and total-budget enforcement, causal inspection, and pretraining/SFT/DPO checkpoint/export/resume. Real CUDA FP16/BF16 cases are included in the G4 startup tests; they skip without GPU hardware. No physical Blackwell benchmark was run on the CPU-only development machine.
